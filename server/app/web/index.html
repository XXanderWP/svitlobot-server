Перевірка налаштувань

Перевіряє доступність ESP32 та IP, ключ Світлобота, токен бота й права бота в каналі.

    Налаштування

    Початкові значення приходять із .env на сервері (його формує GitHub Action із секретів). Те, що ви змінюєте тут, зберігається в .env.override і має пріоритет. Мітка .env — значення з файлу, панель ↺ — змінено тут (натисніть, щоб повернути значення з .env).
    Світлобот
    Видається ботом Світлобота під час створення каналу.
    Змінюйте лише якщо Світлобот змінив адресу API.
    Об'єкт перевірки
    Має збігатися з --mode, обраним під час прошивки.
    Цю адресу сервіс пінгує, щоб відрізнити відсутність світла від відсутності інтернету.
    Через кому, як у --upnp-ports. ESP32 відкриває перший вільний, сервер перевіряє всі.
    Вкажіть цю адресу і порт під час прошивки: --server, --server-port. Порт має бути відкритий у фаєрволі VPS.
    Якщо стуку не було довше — вважаємо, що ESP32 не відповідає (рекомендовано ≥ 3 інтервалів стуку).
    Необов'язковий ключ доступу до сторінки — той самий, що в --key.
    Обов'язковий ключ підпису стуків — той самий, що в --key (CLI генерує його, якщо не вказати). Новий ключ треба записати і в ESP32: svitlo-flasher configure --key ….
    TCP — якщо роутер не відповідає на пінг.
    Будь-який порт, що відповідає, коли світла немає (не порт ESP32).
    Стільки перевірок поспіль мають дати однаковий результат.
    Telegram (необов'язково)
    Від @BotFather. Бот має бути адміністратором каналу.
    Змінні: {status} — поточний стан, {last_status} — останній відомий, {duration} — тривалість без зв'язку, {time} — час події (ГГ:ХХ), {date} — дата.
