## Що це за проєкт

**SvitloBot Monitor** — система для точного визначення наявності електроенергії для сервісу [Світлобот](https://svitlobot.in.ua).

### Проблема

Класичний підхід: ESP32 вдома періодично «пінгує» API Світлобота. Коли пінги припиняються — Світлобот вважає, що світла немає. Але пінги припиняються і тоді, коли **зникає інтернет**, а не світло. Через це в каналі з'являються хибні повідомлення про відключення.

### Рішення

Перевірку переносимо на окремий VPS (поза домашньою мережею):

| ESP32 на зв'язку | Пінг IP (роутер) | Висновок |
|---|---|---|
| так | — | **Світло є** |
| ні | відповідає | **Світла немає** (роутер на ДБЖ живий, ESP32 знеструмлений) |
| ні | не відповідає | **Невідомо** — зник інтернет |

«На зв'язку» залежить від режиму роботи ESP32:
- `upnp` (типово) — ESP32 сам відкриває порт на роутері через UPnP, сервер звертається до його сторінки;
- `push` — ESP32 сам періодично надсилає на сервер підписаний «стук».

Сервіс на VPS сам надсилає пінги в API Світлобота, коли світло є, і не надсилає, коли світла немає. У стані «невідомо» поведінка налаштовується (за замовчуванням — зберігати останній відомий стан, щоб не було хибних відключень). Додатково сервіс може повідомляти Telegram-канал (тихо, з `disable_notification`) про втрату й відновлення інтернет-з'єднання.

## Компоненти

### 1. Прошивка ESP32 (`firmware/`)

- PlatformIO + фреймворк Arduino, два середовища: `esp32dev` (класичний ESP32) і `esp32s3` (ESP32-S3,
  образ для 4 МБ flash у режимі **DIO** — у режимі QIO завантажувач S3 зациклюється з `ets_loader.c 78`;
  `Serial` — UART0 через USB-UART міст, `ARDUINO_USB_CDC_ON_BOOT=0`).
- Файли: `main.cpp` (налаштування, UART-протокол, Wi-Fi, HTTP), `config.h` (спільна структура `Config`),
  `upnp.cpp` (власний мінімальний клієнт UPnP IGD: SSDP → опис → SOAP), `push.cpp` (стуки з HMAC).
- Налаштування (Wi-Fi, режим, порти, ключ, сервер, статичний IP) зберігаються в NVS (`Preferences`, простір імен `svb`). У прошивці **немає** зашитих паролів.
- **Режим upnp:** перебирає зовнішні порти з `upnp_ports`; порт, зайнятий іншим пристроєм
  (`GetSpecificPortMappingEntry` або помилка 718), пропускає; перший вільний відкриває на локальний `port`.
  Оренда 3600 с (або безстрокова, якщо роутер повертає 725), поновлення кожні 20 хв, повтор при збої — через 5 хв.
  Сервер перевіряє всі порти списку, тому знати обраний йому не треба.
- **Режим push:** `POST http://<server>:<server_port>/hb` кожні `push_interval` с; заголовки `X-Svitlo-Ts`
  (Unix-час, синхронізується через NTP) і `X-Svitlo-Sig` = hex(HMAC-SHA256(key, "<ts>\n<тіло>")).
  Сервер відхиляє невірний підпис, розбіжність часу > 300 с і повтор (ts ≤ попереднього).
- Піднімає HTTP-сервер (типово порт `8080`) з ендпоінтом `GET /status` (та `/`), що повертає JSON:
  `{"status":"ok","device":"svitlobot-esp32","version":"…","uptime_s":…,"rssi":…,"message":"Світло є"}`.
- Якщо задано ключ доступу — вимагає `?key=…` або заголовок `X-Svitlo-Key`, інакше `403`.
- Перезавантажується, якщо Wi-Fi недоступний довше 5 хвилин.
- **Протокол налаштування через UART** (115200 бод, рядки з `\n`):
  - пристрій → `SVB:READY <версія>` після старту, `SVB:NOCONFIG` якщо немає налаштувань, `SVB:CONNECTING <ssid>`, `SVB:IP <адреса>`, `SVB:WIFI_TIMEOUT`;
  - пристрій → `SVB:UPNP OK <зовн. порт> <зовн. IP>`, `SVB:UPNP_CGNAT <IP>`, `SVB:UPNP FAIL <причина>`, `SVB:PUSH OK|FAIL <опис>` (при зміні стану);
  - `SVB:PING` → `SVB:PONG`;
  - `SVB:GET` → `SVB:INFO {json без пароля}`;
  - `SVB:SET {json}` → `SVB:OK` (зберігає й перезавантажується) або `SVB:ERR <причина>`;
  - `SVB:CLEAR` → `SVB:OK` (стирає налаштування й перезавантажується).
  - Поля JSON для `SET`: `ssid`, `password`, `port`, `key`, `hostname`, `ip`, `gateway`, `subnet`, `dns`,
    `mode` (`upnp`|`push`), `upnp_ports` (рядок через кому), `server`, `server_port`, `push_interval`.

Збирання: `cd firmware && pio run`.

### 2. CLI-утиліта (`cli/`)

- Python ≥ 3.9, залежності: `esptool` (4.x), `pyserial`. Працює на macOS, Windows, Linux.
- Команда `svitlo-flasher` з підкомандами: `ports`, `flash`, `configure`, `info`, `reset-config`, `monitor`.
- Режим обирається `--mode upnp|push` (типово upnp); для push без `--key` ключ генерується (hex).
  Після налаштування CLI чекає `SVB:UPNP …` / `SVB:PUSH …` і пояснює результат.
- `flash` визначає чип (esptool), записує відповідний об'єднаний образ `svitlo_flasher/firmware/svitlobot-<чип>.bin`
  (`esp32`, `esp32s3`) за адресою `0x0`, потім передає налаштування по UART.
- Образ прошивки готує `cli/scripts/build_firmware.py` (запускає `pio run` і `esptool merge_bin`). Сам `.bin` у git не комітиться — його збирає CI (`.github/workflows/release.yml`) або розробник локально.

### 3. Сервіс моніторингу (`server/`)

- Python 3.12, FastAPI + uvicorn, httpx. Запуск через `docker compose up -d`.
- **Джерела налаштувань** (кожне наступне перекриває попереднє): типові значення → змінні оточення →
  `/config/.env` (монтується з `./.env` лише для читання; на сервері його створює GitHub Action) →
  `/data/.env.override` (зміни з веб-панелі). Сервіс **ніколи не пише в `.env`**, лише в `.env.override`.
  Відповідність полів і змінних — `ENV_KEYS` у `app/config.py` (напр. `TARGET_IP`, `SVITLOBOT_TOKEN`,
  `TELEGRAM_BOT_TOKEN`, `SVITLOBOT_CHANNEL` — ID Telegram-каналу).
- Секрети не передаються як змінні оточення контейнера і не копіюються в образ (`.dockerignore`).
- Стан і журнал подій — у `/data/state.json` (том `./data`).
- Веб-інтерфейс (`app/web/index.html`, чистий HTML/JS без збирання) захищений HTTP Basic Auth
  (`PANEL_USERNAME`/`PANEL_PASSWORD` лише з `.env`; якщо пароль не задано — генерується й пишеться в лог).
  Показує джерело кожного значення, дозволяє скинути перевизначення і має діагностику «Перевірити все».
- Основні модулі:
  - `app/logic.py` — чиста логіка: класифікація стану, антидребезг (підтвердження N перевірками поспіль), рішення «пінгувати Світлобот чи ні». Покрита тестами.
  - `app/checks.py` — перевірка HTTP-сторінки ESP32 (одночасно на всіх портах списку), ICMP-пінг (`ping` з iputils) або TCP-перевірка.
  - `app/heartbeat.py` — перевірка підпису стуків і FastAPI-застосунок `/hb`; запускається другим
    uvicorn-сервером у тому ж процесі (`main.py`, порт `HEARTBEAT_LISTEN_PORT`, типово 8081), щоб панель
    можна було сховати, а порт стуків — лишити відкритим.
  - `app/monitor.py` — два асинхронні цикли: перевірки та надсилання пінгів у Світлобот; обробка переходів між станами, повідомлення в Telegram.
  - `app/svitlobot.py`, `app/telegram.py` — клієнти зовнішніх API.
  - `app/config.py` — модель налаштувань (pydantic) і сховище з `.env` / `.env.override`.
  - `app/envfile.py` — читання/запис файлів `.env` (сумісно з Docker Compose).
  - `app/main.py` — FastAPI, REST API для веб-інтерфейсу.
- API Світлобота: `GET https://api.svitlobot.in.ua/channelPing?channel_key=<ключ>`. URL налаштовується у веб-інтерфейсі (шаблон з `{key}`) на випадок змін з боку Світлобота.
- Режим ESP32 у сервері — поле `device_mode` (`DEVICE_MODE`); у режимі push «ESP32 на зв'язку» означає
  прийнятий стук за останні `push_timeout` секунд.
- Стани: `on` (світло є), `off` (світла немає), `unknown` (немає зв'язку). Політика для `unknown`: `keep_last` (типово), `stop`, `assume_on`.

### 4. Деплой (`.github/`)

- `workflows/deploy.yml` — при пуші в `main`: тести → перевірка збирання образу → деплой по SSH.
- `scripts/make_env.py` — формує `.env` і `compose.env` із секретів; друкує лише назви змінних.
- `scripts/remote_deploy.sh` — на сервері: оновлює код у `PROJECT_FOLDER`, кладе `.env` (600),
  запускає `docker compose --env-file compose.env up -d --build --force-recreate`, чекає healthcheck.
- **Правило безпеки:** жоден крок не має виводити секрети — без `set -x`, `cat .env`, `docker compose config`,
  `docker compose logs`, `docker inspect` у workflow. Секрети передаються в кроки лише через `env:`.
  Compose на сервері запускається з `--env-file compose.env`, щоб не розбирати `.env` із секретами.
- `workflows/release.yml` — збирання прошивки та CLI для релізів (за тегом `v*`).

## Робота з кодом

- Тести сервера: `cd server && python -m pytest`.
- Локальний запуск сервера без Docker: `cd server && pip install -r requirements.txt && ENV_FILE=./.env DATA_DIR=./data uvicorn app.main:app --reload --port 8080`.
- Перевірка CLI: `cd cli && pip install -e . && svitlo-flasher --help`.
- Секрети (токени, ключі, паролі) ніколи не комітимо. `.env`, `compose.env` і `server/data/` — у `.gitignore`.
- Нове поле налаштувань: додати в `Settings`, у `ENV_KEYS`, у форму `index.html` і, якщо це секрет, у `SECRET_FIELDS`.
- Нова логіка станів — спочатку в `app/logic.py` як чиста функція з тестом.
- Не додавайте залежностей без потреби; веб-інтерфейс лишається одним HTML-файлом без збирача.
- Пам'ятайте про головне правило: **усе українською**.
